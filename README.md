# DCOMP320 – Stacks Implementation

A command-line Python program that reads mathematical expressions from `input.txt`, evaluates each one using a **stack-based algorithm**, and writes the results to `output.txt`.

Individual assignment for DCOMP320 – Data Structures and Algorithm, Limkokwing University of Creative Technology, Sierra Leone.

## Main features

- A `Stack` class with `push()`, `pop()`, `peek()`, `is_empty()` and `size()`.
- Clear errors when `pop()` or `peek()` is used on an empty stack.
- Expression evaluation with an operand stack and an operator stack (no `eval()` or `exec()`).
- Operator precedence, left-to-right associativity and parentheses.
- Multi-digit numbers, decimal numbers, whitespace and unary minus (e.g. `-3 + 5`).
- Several expressions per file, separated by lines such as `-----`.
- Invalid expressions are reported on their own line and the rest of the file is still processed.

## Python requirements

- Python 3.8 or newer (developed and tested with Python 3.12.10).
- Standard library only. Nothing needs to be installed.

## How to run the program

Open a terminal in the project folder and run:

```
python main.py
```

The program reads `input.txt` and creates (or overwrites) `output.txt`. It then prints a summary such as:

```
Processed 3 expression(s) with 0 error(s).
Results written to output.txt
```

## Input-file format

- One expression per line.
- Expressions are separated by a **separator line**: a line containing only dashes, at least three (e.g. `-----`).
- Blank lines are allowed.

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

## Output-file format

The output has **one line for every input line**, in the same order.

- An expression line becomes its result on its own line.
- A separator line is copied unchanged.
- A blank line stays blank.
- Whole-number results have no decimal part (`13`, not `13.0`). Other results keep their decimals (`3.75`).

```
13
-----
16
-----
-10
```

> **Note:** the sample output image in the assignment brief shows `17` for `(8 / 4) + 7 * 2`. The correct value is 8 ÷ 4 + 7 × 2 = 2 + 14 = **16**, which is what this program calculates.

## Supported operators

| Symbol      | Meaning                    | Precedence                |
| ----------- | -------------------------- | ------------------------- |
| `( )`       | Parentheses                | Highest (evaluated first) |
| `-` (unary) | Negative number, e.g. `-3` | 3                         |
| `*` `/`     | Multiply, divide           | 2                         |
| `+` `-`     | Add, subtract              | 1                         |

Operators of equal precedence are evaluated left to right (`10 - 3 - 2` = `5`).

## How the stack-based algorithm works

The program uses two stacks: an **operand stack** (numbers) and an **operator stack** (operators and `(`).

1. `tokenize()` splits the expression into numbers, operators and parentheses.
2. The tokens are read from left to right:
   - **Number:** push it onto the operand stack.
   - **`(`:** push it onto the operator stack.
   - **Operator:** while the operator on top of the stack has the same or higher precedence, apply it first. Then push the new operator.
   - **`)`:** apply operators until the matching `(` is found, then remove the `(`.
3. After the last token, apply all remaining operators.
4. The one number left on the operand stack is the answer.

To apply an operator, the program pops two numbers (right one first), calculates, and pushes the result back. For example, `3 + 5 * 2`:

| Token          | Operand stack | Operator stack |
| -------------- | ------------- | -------------- |
| 3              | 3             |                |
| +              | 3             | +              |
| 5              | 3, 5          | +              |
| \*             | 3, 5          | +, \*          |
| 2              | 3, 5, 2       | +, \*          |
| end: apply `*` | 3, 10         | +              |
| end: apply `+` | 13            |                |

## Error-handling behaviour

An expression that cannot be evaluated is written as `Error: <message>` on its own line. The separators and the other results stay in place.

Example input:

```
1 + 1
-----
5 / 0
-----
(2 + 3
```

Example output:

```
2
-----
Error: Division by zero
-----
Error: Unmatched '('
```

| Problem                      | Output line                               |
| ---------------------------- | ----------------------------------------- |
| Division by zero             | `Error: Division by zero`                 |
| Missing `)`                  | `Error: Unmatched '('`                    |
| Extra `)`                    | `Error: Unmatched ')'`                    |
| Operator at the end (`2 +`)  | `Error: Expression ends with an operator` |
| Two numbers in a row (`2 3`) | `Error: Missing operator before number`   |
| Unknown character (`2 + a`)  | `Error: Invalid character 'a'`            |
| Bad number (`1..2`)          | `Error: Invalid number '1..2'`            |

If `input.txt` is missing, the program prints `Error: input file not found: <path>`, exits with code 1 and does not create `output.txt`.

## Assumptions and limitations

- The input file must be named `input.txt` and be in the same folder as `main.py`.
- Only `+`, `-`, `*`, `/` and parentheses are supported (no powers, functions or variables).
- Numbers are stored as Python floats, so results are rounded to 10 decimal places when written.
- Separator lines need at least three dashes. A line such as `--` is treated as an (invalid) expression.
- Unary minus is accepted, so `--3` evaluates to `3`.
- Implicit multiplication such as `2(3)` is rejected.
- `output.txt` is overwritten each time the program runs.
